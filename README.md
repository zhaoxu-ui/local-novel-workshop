# 本地小说工坊

当前版本：`v0.7.0 真实创作验收版`

本地小说工坊是一个面向中文长篇小说创作的本地 Web 工具。它把 Markdown 小说资料库、Codex 直连、cc-switch 配置、本地模型接口和发布稿导出串成一条工作流。

所有项目文件都保存在本机，不依赖数据库，不默认上传云端。

第一次使用建议先看：

```text
使用教程.md
```

README 主要说明项目能力、目录结构和技术细节；`使用教程.md` 按实际写作流程一步步带你操作。后续功能按 `ROADMAP.md` 版本路线推进，当前版本范围见 `CURRENT_ITERATION.md`。

## 启动

```powershell
cd <你的项目目录>
npm start
```

打开：

```text
http://127.0.0.1:8787
```

## Windows x64 安装包

安装依赖后执行：

```powershell
npm install
npm run pack:win
```

安装包输出到：

```text
release/本地小说工坊 Setup 0.3.0.exe
```

桌面安装版会内嵌本地服务并打开桌面窗口，不需要手动执行 `npm start`。安装版的小说项目默认保存在：

```text
文档\本地小说工坊\projects
```

如果 Electron 下载较慢，可以临时使用镜像源：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
npm install
npm run pack:win
```

## Docker 部署

构建并启动：

```powershell
cd <你的项目目录>
docker compose -p local-novel-studio up -d --build
```

查看状态：

```powershell
docker ps --filter name=local-novel-studio
docker logs --tail 80 local-novel-studio
```

停止：

```powershell
docker compose -p local-novel-studio down
```

Docker 版会挂载：

```text
./projects -> /app/projects
C:\Users\你的用户名\.codex -> /root/.codex
C:\Users\你的用户名\.cc-switch -> /root/.cc-switch
```

如果需要让容器提示宿主机项目路径，可以复制 `.env.example` 为 `.env`，并填写：

```text
HOST_PROJECTS_DIR=<你的项目目录>\projects
```

注意：Docker 容器不能直接弹出宿主机资源管理器，所以“打开项目文件夹”会提示你复制路径；使用“复制项目路径”即可定位到宿主机目录。

## 当前能力

- 创建本地小说项目。
- 演示小说项目：一键创建带 10 章规划、样章、长期记忆、封面资料和验收报告的示例项目。
- 根据原始思路自动孵化书名、类型、标签、封面描述、卖点、主角方案和前三章方案。
- 未选择项目时，创意孵化可以自动创建项目。
- 档案助手：创建项目时可自动推荐或手动选择，后续也可切换当前项目的助手。
- 直接调用本机 `codex exec`，继承 `~/.codex/config.toml` 和 cc-switch 当前配置。
- 也可调用 Ollama、LM Studio 等本地模型接口。
- 提供项目状态、配置诊断、任务中心和审核状态。
- 提供控制面、长期记忆和运行时产物管理，包含作者意图、当前焦点、七类记忆 JSON 和每次运行的 intent/context/rule-stack/trace。
- 资料投喂：上传小说规则、平台限制、审稿标准等资料，由 AI 综合判断后沉淀为项目能力包、工作流、多角色协作和项目 SKILL。
- 文风模仿：粘贴作者自己的样稿或本项目确认正文，提取高层风格画像，写入 `05_提示词/文风模仿档案.md` 和 `04_连续性/style_memory.json`。
- 故事圣经：表单化维护人物、剧情线、读者承诺和世界规则，写回 `character_state.json`、`plot_threads.json`、`reader_promises.json`、`world_state.json`。
- 项目保险箱：在大改资料、运行流水线或恢复旧版本前创建快照，支持恢复和删除。
- 章节看板：从章节目录、结构化规划和已有正文自动合并章节进度，点击章节可直接载入编辑区。
- 全局搜索：跨总控、正文、设定、提示词、发布稿、Codex 与运行时产物搜索关键词，点击结果可直接打开文件。
- AI 任务中心：汇总 Codex 运行历史、流水线、资料投喂、修订、质检、发布和维护任务，优先读取 `09_运行时/tasks.json` 任务索引。
- 任务队列增强：支持按任务类型/状态筛选、运行中自动刷新、查看任务详情、失败任务一键重试和 Codex 任务取消。
- 创作雷达：基于本地题材规则、套路风险、去 AI 腔和健康检查思路，扫描人味、题材适配、节奏、连续性和发布准备度。
- 编辑区自动保存：写作时自动备份当前 brief 和正文到 `09_运行时/autosave/current-draft.md`，不覆盖正式章节。
- 管理总纲、人物、设定、连续性、伏笔、情绪账本、提示词和发布稿。
- 写作统一走多阶段流水线：规划、编排、写作、审计、修订、状态同步。
- 状态同步人工审核：把 `state-sync.md` 拆成可勾选类别，应用前自动创建快照，只把确认过的内容写入长期记忆。
- 状态同步差异预览：应用前可预览目标文件、追加/合并方式、写入前数量和预计写入后数量，确认影响范围后再应用。
- 发布前质检：本地扫描当前章节或全书，检查字数、标题、brief、结尾钩子、AI 感风险词、长段落、重复起手式和连续性文件完整度。
- AI 深度质检：读取“AI 执行配置”，用 Codex 直连或本地模型复核人物动机、情绪推进、剧情空转、发布风险和建议修订任务单。
- 修订发布：从质检报告生成修订任务单，一键启动修订流水线，修订前自动快照并保存旧稿历史版本。
- 正文版本管理：查看历史版本、打开旧稿、与当前正文对照、恢复历史版本。
- 批量任务与冲突看板：批量质检章节，生成记忆冲突报告，检查人物/时间线重复、伏笔和未解决问题积压。
- 记忆冲突修复：对“人物状态重复”支持生成修复方案、自动创建安全快照、合并重复记录并输出修复报告。
- 发布资料增强：生成发布资料包，支持按章节范围导出带标题的 TXT / MD 发布稿。
- 发布前总检查：检查章节连续、标题、字数、简介、标签和封面描述，输出可处理清单。
- 完整备份包：把项目资料和正文整理到本地备份目录，并排除本地敏感配置、依赖目录和安装包输出。
- 发布包清单：统一生成 TXT、MD、简介、标签、封面提示词和发布注意事项入口。
- 项目维护：保存模型预设、克隆项目，并在 AI 任务中心查看 Codex 运行记录和日志入口。
- 工程治理：补充服务端/前端模块边界文件、最小 E2E 检查、长期记忆 JSON schema 校验和故障诊断报告。
- JSON schema 校验：检查长期记忆 JSON 的根结构、关键数组字段和版本字段，避免模型写坏记忆文件。
- 故障诊断报告：集中输出配置诊断、长期记忆校验和失败/取消任务，保存到 `09_运行时`。
- 导出 TXT / MD 发布稿。

## Web 界面

界面分为三块：

- 左侧：项目库、新建项目和创意孵化。
- 中间：常用资料快捷入口、章节信息、本章 brief、多阶段流水线、正文 / 修订结果。
- 右侧：默认显示写作流程工具。低频的项目设置、质量记忆、修订版本、发布准备和系统维护入口收进“更多工具”。

顶部操作区提供：

- AI 执行配置：统一管理 Codex 直连和本地模型接口。选择 Codex 直连时，不显示本地模型接口配置。
- 隐藏/显示项目栏、隐藏/显示工具栏：用于简化写作视图。
- 打开项目文件夹、复制项目路径、导出 TXT / MD。

右侧工具区顶部提供两个层级：

- 写作流程：默认视图，只保留章节看板、全局搜索、AI 任务中心和状态同步审核。
- 更多工具：展开后可切换项目设置、质量与记忆、修订版本、发布准备、系统维护。档案助手、资料投喂、文风模仿、召回调试、快照、正文版本、配置诊断、项目维护等低频操作都在这里。

中间快捷入口包括：

- 立项建议
- 封面资料
- 创作总纲
- 主角卡
- 档案助手
- 作者意图
- 当前焦点
- 最新运行时
- 最新 Codex 结果

右侧“项目文件”面板可以直接打开任意 Markdown / TXT 文件。

右侧还包括：

- 项目状态：显示阶段、审核状态、正文数、字数、文件数、Codex 产物数。
- 章节看板：显示章节状态、brief、钩子、正文文件和字数，点击章节可载入编辑区。
- 全局搜索：输入关键词后搜索整个项目资料库，结果可点击打开。
- AI 任务中心：集中查看 Codex 运行历史、流水线、资料投喂、修订、质检、发布和维护任务产物；新任务会写入 `09_运行时/tasks.json`，旧项目仍会兼容扫描已有产物。
- 创作雷达：无需模型即可扫描当前正文或最近章节，输出人味、题材、节奏、连续性、发布准备度分数和风险建议。
- 文风模仿：从作者授权样本或本项目正文提取节奏、句式、对话密度、细节偏好和禁用表达；流水线会在 `context.json` 的 `recalledMemory` 中自动召回。
- 故事圣经：通过分区表单查看和维护人物、剧情线、读者承诺、世界规则，减少直接手改 JSON 的成本。
- 长期记忆召回：每次运行会按当前 brief 排序召回相关人物、伏笔、剧情线程、读者承诺、相似章节和情绪记录，写入 `recalledMemory.ranked`。
- 召回调试：按当前章节号、标题、brief 和正文草稿预览 `recalledMemory.ranked`，运行 AI 前就能看到会读到哪些记忆；关键条目可钉选为本章必读，写入 `04_连续性/memory_pins.json`，运行时进入 `recalledMemory.pinned`；不适合本章的条目可排除，写入 `04_连续性/memory_exclusions.json`，运行时进入 `recalledMemory.excluded` 并从本章召回中过滤。
- 状态同步审核：可先“预览差异”，查看每个目标文件会追加或合并多少内容，再应用选中项。
- 项目保险箱：创建项目快照；恢复快照时会先自动创建一份恢复前快照。
- 配置诊断：按当前“AI 执行配置”检查对应能力。Codex 模式检查 Codex 命令、小说技能、Codex 模型和核心文件；本地模型模式检查本地模型接口和核心文件。
完整操作步骤见 `使用教程.md`。

整体功能审阅、重复入口合并记录和后续能力缺口见 `项目审阅报告.md`。

版本路线和当前迭代：

- `ROADMAP.md`：按版本列出后续能力，权重从高到低。
- `CURRENT_ITERATION.md`：当前 v0.3.0 的范围、出口标准和不做事项。

顶部按钮：

- 打开项目文件夹：请求系统打开当前项目目录。
- 复制项目路径：把当前项目目录复制到剪贴板；如果浏览器不允许写入剪贴板，会把路径放进正文框。
- 导出 TXT / MD：导出 `01_正文` 下的章节。

## AI 执行配置

顶部“AI 执行配置”统一管理两套执行方式：

- Codex 直连：调用本机 `codex exec`，继承 `~/.codex/config.toml` 和 cc-switch 当前配置。
- 本地模型接口：调用 Ollama、LM Studio 或其他兼容接口。

配置项：

- 默认执行方式
- Codex 当前配置状态：仅 Codex 直连模式显示。
- 本地模型名：仅本地模型接口模式显示。
- 本地模型接口：仅本地模型接口模式显示。

点击“保存执行配置”后，会写入当前项目的 `project.json`。项目顶部摘要会显示当前默认执行方式。

## 档案助手

档案助手负责维护项目资料、连续性和后续 AI 生成时需要遵守的档案规则。

它不是凭空生成的新能力。创建或切换助手时，工具会读取本机当前可用的小说相关 Skill，优先从 `.cc-switch/skills` 读取，再从 `.codex/skills` 读取，例如：

- `novel-writing-polisher`
- `novel-ai-reviewer`

助手档案只作为这些 Skill 的项目档案补充层，用来记录当前项目的资料维护重点、边界和检查清单。

创建项目时可以选择：

- 自动推荐：根据项目名、类型和初始创意选择默认助手。
- 通用档案管家
- 网文连载档案官
- 悬疑伏笔档案官
- 人物关系档案官
- 世界观设定官
- 同人设定守门人

项目创建后会生成：

```text
05_提示词/档案助手.md
```

在右侧“档案助手”面板可以随时切换当前项目助手。切换后会更新 `project.json`，并重新写入 `05_提示词/档案助手.md`。

后续多阶段流水线和资料投喂都会默认读取这个助手档案。

## 控制面与长期记忆

项目现在会维护两个控制面文件：

```text
00_总控/author_intent.md
00_总控/current_focus.md
```

- `author_intent.md`：记录这本书真正想写什么、读者承诺、不想写成什么、长期边界。
- `current_focus.md`：记录当前阶段、近期重点、本轮最重要的问题、暂时不要处理的问题。

长期记忆采用 Markdown + JSON 混合：

```text

04_连续性/plot_threads.json
04_连续性/world_state.json
04_连续性/style_memory.json
04_连续性/reader_promises.json
```

这些文件会被多阶段流水线默认读取。

## 项目保险箱

项目保险箱用于保护长篇创作过程中的关键节点。建议在这些操作前创建快照：

- 运行多阶段流水线前。
- 大改总纲、人物、世界观、伏笔表前。
- 执行资料投喂前。
- 准备恢复旧版本前。

快照保存在项目目录外部：

```text
projects/.snapshots
```

不会出现在项目文件列表里，也不会被打包进 GitHub 发布内容。

恢复快照时，系统会先自动保存当前项目状态为“恢复前自动快照”，再用目标快照覆盖当前项目。这样即使恢复错了，也仍然有机会回到恢复前状态。

## 章节看板

章节看板用于管理整本书的章节推进。它会合并三类信息：

- `00_总控/chapters.json`：结构化章节规划。
- `00_总控/章节目录.md`：Markdown 章节目录。
- `01_正文`：已经保存的正文文件。

章节状态包括：

```text
未规划 / 已规划 / 生成中 / 待审 / 可发布
```

在编辑区填写章节号、标题和本章 brief 后，点击“保存章节规划”，会更新：

```text
00_总控/chapters.json
00_总控/章节目录.md
```

点击看板里的章节，会自动把章节号、标题、brief 和已有正文文件载入编辑区。保存章节正文后，看板会自动关联对应正文文件并更新字数。

## 运行时产物

每次执行创意孵化、资料投喂或多阶段流水线前，系统会编译一组运行时产物：

```text
09_运行时/第章节号章_标题/run_时间戳_任务/
  intent.md
  context.json
  rule-stack.yaml
  trace.json
```

- `intent.md`：本轮任务意图、章节、brief、当前草稿摘要。
- `context.json`：本轮读取了哪些控制面、长期记忆、项目规则和额外资料，并在 `recalledMemory.ranked` 中列出相关人物、伏笔、剧情线程、读者承诺、相似章节和情绪记录。
- `rule-stack.yaml`：本轮规则优先级，包含用户要求、作者意图、当前焦点、档案助手、项目规则、长期记忆。
- `trace.json`：记录编译、执行、审计、状态同步等阶段，后续可扩展成完整写作流水线。

右侧“状态同步审核”面板会列出最近的同步记录：

- 已应用：状态同步已经写入长期记忆。
- 需复核：AI 输出了同步内容，但没有自动写入，建议人工打开报告检查。
- 失败：流水线某个阶段失败，通常可从 trace 查看错误。
- 未完成：运行时产物已生成，但还没有完成同步。

面板提供快捷入口打开 `trace.json`、`state-sync-apply.md`、`state-sync.md` 和 `revision.md`。

如果某次运行生成了 `state-sync.md` 或 `state-sync-apply.md`，可以点击“审核同步”。系统会解析其中的 JSON，并按类别展示：

- 章节日志
- 情绪账本
- 伏笔回收
- 故事状态
- 人物状态
- 时间线
- 剧情线程
- 世界状态
- 风格记忆
- 读者承诺

每个类别下面还会拆出具体条目或字段，例如单条读者承诺、单个风格字段、某个人物状态更新。勾选后点击“应用选中”，系统会先在“项目保险箱”创建一份应用前快照，再只把勾选条目写入 `04_连续性` 和相关控制面文件。没有勾选的内容不会写入，无法解析为 JSON 的同步建议也不会自动污染长期记忆。

面板上方还有“流水线流程图”，会把最近一次运行显示成节点：

```text
意图 -> 上下文 -> 规则栈 -> 规划 -> 编排 -> 写作 -> 审计 -> 修订 -> 同步
```

绿色代表已完成，黄色代表需复核，红色代表失败，灰色代表未完成。可点击的节点会直接打开对应运行时产物。

流程图下方是“运行详情”面板，会把一次运行集中成标签页：

- 意图：`intent.md`
- 上下文：`context.json`
- 规则栈：`rule-stack.yaml`
- 规划：`plan.md`
- 编排：`orchestration.md`
- 草稿：`draft.md`
- 审计：`audit.md`
- 修订：`revision.md`
- 同步：`state-sync.md`
- Trace：`trace.json`

可用标签会直接预览文件内容，也可以点击“打开当前”跳转到项目文件视图。

## 多阶段流水线

点击“运行多阶段流水线”会读取“AI 执行配置”的默认执行方式。

Codex 直连模式会启动本机 `codex exec`，并要求 Codex 按以下阶段写入运行时产物：

```text
plan.md
orchestration.md
draft.md
audit.md
revision.md
state-sync.md
```

本地模型接口模式会按阶段依次调用本地模型，并把每个阶段结果写入同样的运行时目录。最终修订稿会回填到正文框。

流水线阶段：

1. 规划：明确本章目标、冲突、信息增量、人物变化、结尾钩子。
2. 编排：安排场景顺序、人物出场、信息释放、伏笔和情绪节奏。
3. 写作：生成正文草稿。
4. 审计：检查 AI 感、连续性、人物可信度、节奏、冲突、合规风险。
5. 修订：输出最终可发布章节正文。
6. 状态同步：整理需要写回长期记忆的建议；Codex 模式会尝试直接更新连续性文件。

本地模型模式完成后会自动：

- 保存最终修订稿到 `01_正文`。
- 生成 `state-sync-apply.md`。
- 把合法 JSON 状态同步结果写入章节日志、情绪账本、伏笔回收表和七类长期记忆 JSON。
- 如果状态同步输出无法解析为 JSON，只保留报告并在 `trace.json` 标记为 `needs_review`，不会污染长期记忆。

## 资料投喂

“资料投喂”用于上传小说规则、平台限制、审稿标准、你自己的写作原则等文本资料。

它会读取“AI 执行配置”的默认执行方式：

- Codex 直连：调用本机 `codex exec`，继承 cc-switch/Codex 当前配置。
- 本地模型接口：调用项目保存的本地模型接口。

处理流程：

1. 原始资料先保存到 `08_资料投喂/原始资料`。
2. AI 读取已有项目能力和本次资料，判断资料类型、适用性、冲突和风险。
3. 不会上传什么就吸收什么；与项目冲突、证据不足、过时、侵权/仿写/洗稿风险高的内容会标记为不采纳。
4. 采纳内容会整理为 `05_提示词/项目能力包.md`、`05_提示词/项目工作流.md`、`05_提示词/多角色协作.md` 和 `05_提示词/SKILL.md`。
5. 吸收报告保存到 `08_资料投喂/投喂报告_时间戳.md`。

这些能力文件会被多阶段流水线默认读取。

## 发布到 GitHub 前检查

仓库已提供 `.gitignore`，默认排除：

```text
projects/
.env
.codex/
.cc-switch/
node_modules/
*.log
```

不要把 `projects/` 提交到公开仓库。这里面会包含你的小说项目、运行日志、运行时上下文、本机路径和可能的创作资料。

如果你已经不小心把这些文件加入 Git 暂存区，先取消追踪：

```powershell
git rm -r --cached projects
git rm --cached .env
```

再检查：

```powershell
git status --short
```

发布前建议先跑本地校验：

```powershell
npm run check
npm run smoke
npm run regression
npm run prepare:github
```

其中 `npm run regression` 会使用临时项目目录启动服务并验证项目创建、章节保存、质检、修订任务、发布资料、导出和模型预设等核心接口，不会写入你的真实 `projects/` 数据。`npm run prepare:github` 会生成 `GITHUB_RELEASE_CHECK.md`，用于确认公开发布时不会携带本地配置或小说项目资料。
